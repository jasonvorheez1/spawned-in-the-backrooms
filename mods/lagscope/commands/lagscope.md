name: lagscope
description: Read this game's LAGSCOPE lag reports and fix the top causes
---

1. Take a reading now: `run_script` `ctx.emit("lagscope:scan", { why: "before" })`, wait ~6 s. Every machine in the room saves one report.
2. Read it: `spawn game_db sql "SELECT id, name, place, text FROM lagscope_reports ORDER BY id DESC LIMIT 3"`. The `text` opens with **AI BRIEF v2**: `bound:` says which side holds the frame (gpu, cpu = the renderer's CPU, sim = scripts and physics, hitch, outside, ok), `numbers:`, then up to 10 culprits ranked by impact (a bad sim culprit is never ranked under drawing hints). Each has `who` (kind × count, template, script, example ids, where they stand), `open` (only that culprit's own files), `fix`, `code` (the line to write), `saves` (what goes away, counted, never a guessed ms) and `check` (the number that proves it); no who means `look:` (a spawn perf flag or grep line) says where to find it. Many reports at once: `data.ai.culprits` per row (JSON), keys are stable: game-thread, scripts-per-object, freeze, dynamic-bodies, character-bodies, mesh-colliders, entity-leak, spawn-burst, broken-scripts, shadow-lights, lights, particles, fx-count, triangles, heavy-model, vegetation, render-scale, gpu-memory, draw-calls, no-draw-distance, small-shadows, shadow-casters, skinned-bodies, dense-objects, sprites, hud-layout, memory-leak, gc-churn, state-chatter, audio-loops, download-weight, ping.
3. Fix culprit 1 first, on the side the frame is bound by: a GPU fix does nothing for a script problem. Run the `next reads` the brief names (`spawn perf --script <file>` for a sim culprit, `spawn perf --frame` for a drawing one) before editing: the brief counts what stands, `spawn perf` times it.
4. Prove it: scan again with `{ why: "after" }`, compare `numbers:` and the culprit's `check`. Say what changed with both readings and the report ids; a fix with no second reading is not done.
